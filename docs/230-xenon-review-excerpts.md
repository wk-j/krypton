# Xenon Review Source Excerpts — Implementation Spec

> Status: Implemented
> Date: 2026-08-17
> Milestone: M-ACP — Harness convergence
> Builds on: 211 (Review Board) · 212 (Xenon) · 217 (`#reviews` excerpts)

## Problem

The built-in `#reviews` page (spec 217) renders a line-numbered source excerpt under every walkthrough `at:` and every finding `file:` / `file:line`. Xenon turns the same fences into semantic HTML but stops at the path string. A teammate opening `https://art.bcircle.dev/r/…/review/…` sees the spine of the Board with no code, because Xenon has no working tree to read.

## Solution

Bake excerpts **at `#push` time** on the machine that still has the repo. The publisher walks `review.md` for the same anchors spec 217 already understands, runs the same guards, and attaches a sidecar `excerpts.json` to the published revision (via `LocalResource.inline` — not written back to `.krypton/reviews/`). Xenon's walkthrough/finding renderers look that sidecar up and emit the same `.rv-src` markup the loopback already uses.

Chosen over giving Xenon a checkout (out of spec 212, and a secret-exfiltration surface) and over rewriting `review.md` (would pollute the lane document and desync the in-app Board).

## Research

- Xenon `render_rv_walkthrough` (`~/Source/xenon/src/render.rs:162`) is explicit: *“Anchors are PLAIN TEXT: no jump target exists on a server that does not hold the repo.”* `render_rv_finding` likewise emits only the `file:line` chip. No `.rv-src` CSS exists in `assets/app.css`.
- `#reviews` already solved extraction: `RvSrcCtx` + `rv_anchor` / `excerpt` / `render_rv_excerpt` in `hook_server.rs:6964–7296`. Guards: `validate_doc_path`, extension allowlist, `.gitignore` + `.git/info/exclude`, hard refuse of `.krypton/`, 2 MB / 60-excerpt / ±6 / 40-row / 400-col budgets. That logic must be reused, not copied.
- `#push` already has a place to inject generated bytes: `LocalResource.inline` is hashed, secret-scanned, and uploaded alongside `sources` (`xenon.rs:1038–1040`). Attention flags already use it. A sidecar never has to touch disk.
- Secret pre-scan (`scan_for_secrets`) runs on every UTF-8 body before any blob leaves. An excerpt of a file the repo tracks is the same text `#reviews` already showed locally; a leak is possible only if the human `#push --force`s past a hit, which is existing policy.
- Already-published revisions have no sidecar. Re-push is the upgrade path; Xenon must render those Boards exactly as today (path + say, no empty excerpt shells).

## Prior Art

| App | Implementation | Notes |
|-----|----------------|-------|
| GitHub PR review | Hunk stored on the comment at submit time | Snapshot, not live HEAD — the convention this spec copies. |
| Sourcegraph | Live excerpt at query time | Needs the corpus on the server; Xenon does not. |
| `#reviews` (spec 217) | Live tree at page render + `changed since this review` chip | Correct on loopback; impossible on Xenon. |

**Krypton delta** — `#reviews` stays live-tree. Xenon gets a **publish-time snapshot**, which is the honest artefact for a teammate who will never have this checkout. No syntax highlighting (same as 217). No git-object “as of commit” lookup.

## Design

### Sidecar shape

Keyed by the **exact** `at:` / `file`[+`:line`] string the lane wrote, so Xenon does not re-parse ranges.

```json
{
  "version": 1,
  "anchors": {
    "src/content-focus.ts:28": {
      "label": "src/content-focus.ts:22-34",
      "first_line": 22,
      "anchor_line": 28,
      "lines": ["export function contentRootIsInFocusedWindow(…)", "…"],
      "omitted": 0,
      "stale": false
    },
    "src/gone.ts:1": { "skip": "missing" }
  }
}
```

`skip` is `"missing"` or `"drifted"` (with `file_lines` for the notice). `rejected` / `budget` anchors are **omitted** — same silence as `#reviews`.

`version` is required; Xenon ignores an unknown version rather than guessing.

### Push flow

```
1. collect() builds the review LocalResource from .krypton/reviews/<slug>/
2. If review.md is present:
   a. parse created from frontmatter (same as hook_server)
   b. collect_review_excerpts(cwd, review.md, created_ms)
   c. resource.inline["excerpts.json"] = serde_json::to_vec(sidecar)
3. push_inner hashes + secret-scans every body including excerpts.json
4. commit as today
```

No new `#push` flag. A review with zero resolvable anchors produces `{"version":1,"anchors":{}}`; Xenon treats empty the same as absent.

### Xenon render

`web.rs` already has the revision's file list when it renders `review.md`. If `excerpts.json` exists, parse it once and pass `&ExcerptIndex` into `render_review_blocks`.

- Walkthrough: after each step's `say:`, if the step's `at:` is in the index, append `render_rv_excerpt`.
- Finding: after the head row, look up `file:line` or `file` the same way.
- Markup and Thai chips match hook_server (`ไฟล์นี้ไม่มีแล้ว`, `บรรทัดนี้เลยท้ายไฟล์ — ตอนนี้ไฟล์มี N บรรทัด`, `ไฟล์เปลี่ยนหลังรีวิวนี้`, `อีก N บรรทัด`).
- Malformed sidecar → log + render as today (no excerpts). Never fail the page.

### Extraction reuse

`collect_review_excerpts` walks the raw markdown (not comrak HTML): every ` ```review:walkthrough ` / ` ```review:finding ` fence body, then the same `rv_group` / `rv_scalar` keys hook_server already uses (`- at:`, `file:`, `line:`). One `RvSrcCtx` per push, so a file anchored five times is read once.

## Edge Cases

- **Old revision, no sidecar** — unchanged Xenon page.
- **Sidecar present, unknown `version`** — ignored.
- **Anchor in sidecar but not in this `review.md`** — unused; harmless.
- **Secret in an excerpt** — resource `blocked` with `excerpts.json <hit>`; `--force` still required, same as any other file.
- **Gitignored / `.krypton/` / binary / outside project** — omitted from the sidecar.
- **200 anchors** — first 60 excerpts, rest omitted (budget), no notice file on Xenon (the loopback notice is page-local).
- **`#reviews` after this ships** — unchanged live-tree behaviour; sidecar is push-only.

## Out of Scope

- Syntax highlighting (spec 217).
- Git-object “code as of commit”.
- Serving arbitrary repo files from Xenon.
- Changing the in-app Review Board or the loopback `#reviews` live read.
- Backfilling excerpts onto already-published revisions without a re-push.
- Analysis bundles (no spec-217 excerpts today).
